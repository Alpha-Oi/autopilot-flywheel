## 🎯 Видение

**Autopilot Flywheel** — это открытая платформа, которая превращает одиночного AI-агента для разработки в самообучающуюся мультиагентную фабрику, способную планировать, координировать и выполнять сложные программные проекты с минимальным участием человека.

Мы верим, что будущее разработки ПО — не за одним всемогущим агентом, а за роем специализированных агентов, которые:

- работают параллельно над независимыми частями проекта;
- координируются через общую систему обмена сообщениями и файловых блокировок;
- накапливают коллективный опыт в постоянной процедурной памяти;
- защищены от катастрофических ошибок на уровне рантайма;
- учатся на каждом выполненном задании, становясь эффективнее со временем.

**Autopilot Flywheel — это не просто инструмент. Это маховик (flywheel):** чем больше задач он выполняет, тем умнее становится, тем быстрее и качественнее выполняет следующие задачи. Каждый компонент усиливает остальные, создавая самоподдерживающийся цикл роста.

## 🔥 Проблема

### Текущее состояние AI-агентов для разработки

Современные инструменты — Claude Code, Codex, Cursor, Aider, skills — впечатляют, но остаются принципиально ограниченными:

| Ограничение | Последствие |
|---|---|
| Одиночный агент | Нет параллелизма; один агент делает всё последовательно |
| Нет координации | Несколько агентов перезаписывают работу друг друга |
| Нет постоянной памяти | Каждый запуск начинается «с нуля»; опыт теряется |
| Нет защиты | Агент может выполнить `rm -rf` или `git reset --hard` |
| Линейное планирование | Нет графа зависимостей; нет приоритизации задач |
| Ручное развёртывание | Каждая среда настраивается вручную часами |

`autopilot-jet` (форк `nick-vels/skills`) решает первую часть задачи — полный цикл «идея → спецификация → сборка → проверка» с дашбордом прогресса. Но он остаётся монолитным одиночным агентом, неспособным масштабироваться на сложные проекты.

### Что теряется без мультиагентности

- **Время:** задачи, которые можно выполнять параллельно, выполняются последовательно.
- **Качество:** один агент не может одновременно быть экспертом в бэкенде, фронтенде, тестировании и документации.
- **Обучение:** каждый запуск не оставляет после себя переиспользуемых знаний.
- **Безопасность:** нет механизмов предотвращения конфликтов и деструктивных действий.

## ⏰ Почему сейчас

Три технологических сдвига делают создание Autopilot Flywheel возможным именно сейчас:

1. **MCP (Model Context Protocol) стал стандартом.** Агенты могут подключаться к внешним инструментам через единый протокол. Экосистема Dicklesworthstone построена на MCP, что позволяет интегрировать 7+ инструментов без написания адаптеров для каждого.

2. **Экосистема Flywheel уже существует.** Dicklesworthstone создал полноценный набор из 14+ инструментов для мультиагентной разработки: координацию, память, защиту, оркестрацию и развёртывание. Нам не нужно изобретать всё с нуля.

3. **Мультиагентные архитектуры доказали свою эффективность.** Исследования и практические проекты (AgentMesh, Agent 4, AgentSpawn) показывают, что специализированные агенты, работающие в команде, могут значительно превосходить одиночных агентов в сложных задачах разработки.

## 💡 Решение

Autopilot Flywheel объединяет ядро `autopilot-jet` с 7 инструментами экосистемы Dicklesworthstone, добавляя недостающие слои:

```text
+-----------------------------------------------------+
|  СЛОЙ 5: РАЗВЁРТЫВАНИЕ         -> ACFS             |
+-----------------------------------------------------+
|  СЛОЙ 4: ПАМЯТЬ                -> CASS + CASS Memory|
+-----------------------------------------------------+
|  СЛОЙ 3: КООРДИНАЦИЯ И ЗАЩИТА  -> Agent Mail + DCG |
+-----------------------------------------------------+
|  СЛОЙ 2: ОРКЕСТРАЦИЯ           -> NTM              |
+-----------------------------------------------------+
|  СЛОЙ 1: ПЛАНИРОВАНИЕ          -> Beads Workflow+bv|
+-----------------------------------------------------+
|  ЯДРО: Autopilot Core          -> наследие skills  |
+-----------------------------------------------------+
```

Результат — самообучающаяся мультиагентная фабрика, способная:

- планировать работу как граф задач с зависимостями и приоритетами;
- запускать несколько агентов параллельно (Claude, Codex, Gemini);
- координировать их без конфликтов через файловые аренды;
- защищать от катастрофических ошибок через перехват деструктивных команд;
- накапливать процедурную память между запусками;
- разворачиваться на чистом VPS одной командой за 30 минут.

## 🧭 Ключевые принципы

### 1. Каждый слой независим

Любой компонент можно отключить через CLI-флаг. Если CASS Memory недоступен, Autopilot работает без контекста. Если Agent Mail отключён, агенты работают без координации, но с повышенным риском конфликтов.

### 2. Graceful degradation

Система не падает при отказе одного из компонентов. Она продолжает работать с пониженной функциональностью, логируя проблему.

### 3. Идемпотентность

Повторный запуск не должен ломать состояние. Все операции проектируются так, чтобы их можно было безопасно повторить.

### 4. Аудит всего

Все действия агентов логируются через Agent Mail. Любое решение можно отследить: кто, когда и почему его принял.

### 5. Безопасность по умолчанию

DCG (Destructive Command Guard) включён по умолчанию. Ни один агент не может выполнить `rm -rf` или `git reset --hard` без явного разрешения.

### 6. Обучение на опыте

Каждая выполненная задача — это данные для обучения. CASS Memory дистиллирует сырые сессии в процедурные правила, которые используются в следующих запусках.

## 🧩 Компоненты

### 🔹 Autopilot Core (ядро)

**Происхождение:** форк `Alpha-Oi/autopilot-jet`, основанный на `nick-vels/skills`.

**Функции:**

- принимает идею пользователя в свободной форме;
- задаёт 5–8 уточняющих вопросов;
- пишет спецификацию проекта;
- разбивает работу на таски и передаёт их в Beads Workflow;
- запускает агентов через NTM;
- следит за прогрессом на дашборде;
- проверяет результат против изначальной задачи.

**Что добавляется в Flywheel:**

- вызов `cm context` перед началом каждой задачи;
- делегирование исполнения NTM вместо самостоятельного запуска;
- чтение графа задач из `bv --robot-triage`.

> ⚠️ Требует верификации после завершения `autopilot-jet`: интерфейсы и API ядра могут измениться в процессе разработки.

### 🔹 Beads Workflow

**Репозиторий:** `Dicklesworthstone/beads-workflow`

**Роль:** мост между markdown-планом Autopilot и структурированной системой задач Beads.

**Что делает:**

- конвертирует markdown-спецификацию в beads — задачи с зависимостями;
- полирует задачи до готовности к исполнению;
- обеспечивает единый формат для всех агентов.

Beads — это граф задач с зависимостями, оптимизированный для AI-агентов. Задачи могут быть последовательными через `blocks`, параллельными или связанными иерархически: Epic → Task → Subtask.

### 🔹 Beads Viewer (bv)

**Репозиторий:** `Dicklesworthstone/beads_viewer`

**Роль:** TUI и robot-mode API для анализа графа задач.

**Что делает:**

- строит DAG зависимостей между задачами;
- считает PageRank для приоритизации;
- определяет критический путь;
- показывает канбан-доску.

### 🔹 NTM (Named Tmux Manager)

**Репозиторий:** `Dicklesworthstone/named_tmux_manager`

**Роль:** единая контрольная плоскость для мультиагентной разработки.

**Что делает:**

- спавнит и тайлит агентов Claude, Codex и Gemini в tmux-сессиях;
- предоставляет TUI dashboard для оператора;
- поддерживает checkpointing и восстановление состояния;
- интегрирован с Agent Mail и Beads;
- предоставляет `--robot-*` флаги, REST API, SSE/WebSocket и OpenAPI.

NTM превращает tmux в локальную контрольную плоскость для мультиагентной разработки, объединяя оркестрацию сессий, графовую триажу задач, политики безопасности и рабочие процессы одобрения.

### 🔹 MCP Agent Mail

**Репозиторий:** `Dicklesworthstone/mcp_agent_mail`

**Роль:** «Gmail для кодирующих агентов» — координационный слой.

**Что делает:**

- даёт каждому агенту постоянную идентичность;
- предоставляет входящие/исходящие сообщения и ветки обсуждений;
- реализует файловые аренды (leases): агент объявляет файл перед редактированием;
- предоставляет pre-commit guard, блокирующий коммиты в зарезервированные файлы;
- предоставляет 44 инструмента и 25 ресурсов через MCP.

Agent Mail — это асинхронный координационный слой для AI-агентов, предоставляющий идентичности, inbox/outbox, поиск по истории сообщений и добровольные файловые аренды для предотвращения конфликтов.

### 🔹 DCG (Destructive Command Guard)

**Репозиторий:** `Dicklesworthstone/destructive_command_guard`

**Роль:** защитный слой от катастрофических ошибок агентов.

**Что делает:**

- перехватывает деструктивные команды (`rm -rf`, `git reset --hard`, `dd`, `mkfs`) до выполнения;
- SIMD-ускорен и работает мгновенно;
- zero-config;
- предлагает безопасные альтернативы.

### 🔹 CASS + CASS Memory

**Репозитории:**

- `Dicklesworthstone/coding_agent_session_search`
- `Dicklesworthstone/cass_memory_system`

**Роль:** единый индекс истории сессий + трёхуровневая процедурная память.

**Что делает:**

- CASS индексирует сессии Claude Code, Codex, Gemini, Cursor, Aider и других инструментов;
- CASS Memory реализует переход «эпизодическая → рабочая → процедурная память» с confidence scores;
- MCP-сервер предоставляет инструменты `cm_context`, `cm_feedback`, `cm_outcome`.

CASS Memory трансформирует разрозненные сессии агентов в постоянную кросс-агентную процедурную память. Трёхуровневая когнитивная архитектура позволяет системе не просто запоминать факты, а дистиллировать правила с оценкой уверенности.

### 🔹 ACFS (Agentic Coding Flywheel Setup)

**Репозиторий:** `Dicklesworthstone/agentic_coding_flywheel_setup`

**Роль:** автоматическое развёртывание среды.

**Что делает:**

- превращает чистый Ubuntu VPS в настроенную мультиагентную среду за 30 минут;
- устанавливает все инструменты Flywheel.

## ✨ Что делает Flywheel особенным

### 1. Настоящая мультиагентность

Не «один агент, который делает всё», а рой специализированных агентов, работающих параллельно. NTM управляет сессиями, Agent Mail координирует, DCG защищает.

### 2. Граф задач, а не список

Beads Workflow превращает линейный план в DAG зависимостей. `bv` считает PageRank, чтобы определить, какие задачи критически важны, а какие можно отложить.

### 3. Процедурная память

CASS Memory — это не просто логи. Это трёхуровневая когнитивная архитектура, которая дистиллирует сырые сессии в правила с confidence scores. Система учится на каждом запуске.

### 4. Безопасность на уровне рантайма

DCG блокирует деструктивные команды до их выполнения. Agent Mail предотвращает конфликты через файловые аренды. Система проектируется так, чтобы минимизировать риск случайного уничтожения данных.

### 5. Самоподдерживающийся цикл

Чем больше задач выполняется → тем больше данных для обучения → тем умнее система → тем эффективнее следующие задачи. Это и есть flywheel.

## 🎬 Сценарии использования

### Сценарий 1: Сборка REST API

```text
> Собери мне REST API для управления задачами с аутентификацией

[Autopilot] Уточняющие вопросы: язык, БД, аутентификация...

[Autopilot] 📚 Дистиллировано 3 новых правила в память.
```

### Сценарий 2: Рефакторинг legacy-кода

- Autopilot анализирует существующий код.
- Создаёт граф задач по рефакторингу.
- Запускает несколько агентов для параллельной работы над разными модулями.
- Agent Mail предотвращает конфликты при редактировании общих файлов.

### Сценарий 3: Написание тестов

- Autopilot определяет непокрытые участки кода.
- Создаёт задачи на написание тестов.
- Агенты работают параллельно над разными модулями.
- Результаты проверяются через CI.

## 🧠 Философия

### Почему «Flywheel»?

Термин «flywheel» (маховик) взят из мира стартапов и описывает самоподдерживающийся цикл роста. В контексте Autopilot Flywheel это означает:

1. больше задач → больше данных для обучения;
2. больше данных → умнее система;
3. умнее система → быстрее и качественнее выполняет задачи;
4. быстрее выполняет → можно делать больше задач.

Этот цикл не имеет заданной точки насыщения. Чем дольше работает система, тем больше у неё возможностей улучшать повторяемые рабочие процессы за счёт накопленного опыта.

### Почему не один супер-агент?

Один супер-агент ограничен контекстным окном, скоростью и специализацией. Мультиагентная система может:

- работать параллельно;
- иметь разных агентов для разных задач — бэкенд, фронтенд, тесты;
- использовать разные модели — Claude для рассуждений, Codex для кода, Gemini для анализа;
- не терять контекст при переключении между задачами благодаря внешним слоям состояния и памяти.

### Почему экосистема Dicklesworthstone?

Dicklesworthstone создал набор инструментов для ключевых проблем мультиагентной разработки: координации (Agent Mail), памяти (CASS Memory), оркестрации (NTM), планирования (Beads), безопасности (DCG) и развёртывания (ACFS).

Вместо того чтобы изобретать всё с нуля, Autopilot Flywheel собирает эти компоненты в единый конвейер с независимыми слоями и возможностью последующей замены отдельных подсистем.

## 🤝 Вклад

Проект находится на стадии **vision / design**. Приветствуется:

- идеи по архитектуре — Issues с тегом `architecture`;
- предложения по интеграции — Issues с тегом `integration`;
- документация — PR в `docs/`;
- дизайн дашборда — Issues с тегом `design`;
- тесты и бенчмарки — PR в `tests/`.
